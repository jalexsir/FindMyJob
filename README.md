# DefTech Jobs Bot 🤖

Telegram-бот для пошуку IT/Defence-tech вакансій з бронюванням.
Збирає вакансії з кількох RSS-джерел, усуває дублікати, фільтрує по даті та дозволяє керувати списками вакансій.

---

## Функціонал бота

### Крок 1 — Вибір категорій (`/start`)

Після команди `/start` бот показує діалог вибору категорій пошуку.

**Доступні категорії:** Java, Support, Golang, Integration

- Кнопки розташовані по 2 в рядку (✅/⬜)
- Можна обрати одну або декілька категорій
- Повідомлення оновлюється: `"Ви обрали категорій: Java, Support"`
- Кнопка `▶️ Продовжити (N обрано)` з'являється тільки після вибору мінімум однієї
- Постійне меню внизу заблоковане до підтвердження вибору

### Крок 2 — Пошук вакансій

Після підтвердження категорій — з'являється постійна панель меню:

| Кнопка | Дія |
|--------|-----|
| 📅 Вакансії за 1 день | Сьогодні та вчора |
| 📆 Вакансії за 7 днів | Останні 7 днів |
| 📋 Всі вакансії | Без обмеження по даті |
| 🔍 Вилучені з пошуку | Список прихованих вакансій |
| ⭐ Обране | Список обраних вакансій |
| 🗑 Очистити листування | Видаляє повідомлення, скидає категорії, повертає до кроку 1 |
| 🗑 Очистити список вилучених | Очищає список вилучених (або "Список пустий") |

### Крок 3 — Підтвердження показу

Після натискання кнопки пошуку:
1. Бот завантажує список вакансій і рахує кількість по джерелах
2. Показує **зведення** (без відправки вакансій)
3. Пропонує три дії:
   - `🔄 Переобрати категорії пошуку` — повертає до кроку 1 зі збереженим вибором
   - `❌ Ні` → "Часікі тікають!"
   - `✅ Так` → **тільки тут** завантажуються і відправляються вакансії

### Крок 4 — Перегляд вакансій

Кожна вакансія — окреме повідомлення.

**Картинка (Minecraft-стиль):**
- Синє небо з піксельними хмарами та двома острівцями з деревами
- Жовтий напис `>> Вакансія #N <<`
- Червона плашка `NEW` зліва — для нових (ще не переглянутих) вакансій
- Жовтий напис `* Обране *` внизу — для вакансій в обраному

**Текст:**
- 📌 Вакансія #N
- 💼 Спеціальність
- 🏢 Компанія
- 📍 Місце роботи
- 💰 Зарплата
- 📅 Дата публікації (формат: "20 липня 2026")
- 🌐 Сайт-джерело

**Кнопки під вакансією:**
- 🔗 Відкрити вакансію
- ⭐ Додати в обране / 💛 В обраному (повторний клік — видаляє)
- 🚫 Вилучити з пошуку

### Система "Вилучені з пошуку"

- `🚫 Вилучити з пошуку` → повідомлення замінюється на заглушку з кнопкою `👁 Відновити до перегляду`
- `👁 Відновити до перегляду` → повідомлення відновлюється на місці
- `🔍 Вилучені з пошуку` → список прихованих з кнопкою `♻️ Відновити вакансію` під кожною
- `🗑 Очистити список вилучених` → очищає список або повідомляє "Список пустий"
- Вилучені **не показуються** при наступних пошуках
- Список **персональний** для кожного користувача

### Система "Обране"

- `⭐ Додати в обране` → вакансія потрапляє в персональний список
- `💛 В обраному` → повторний клік видаляє з обраного
- `⭐ Обране` → зведення кількості + питання "Показати?"
  - `✅ Так` → вакансії показуються з міткою `* Обране *` на картинці
  - `❌ Ні` → "⏰ Часікі тікають!"
- Список **персональний** для кожного користувача

### Мітка NEW

- При першому перегляді **всі** вакансії отримують мітку NEW
- При наступних запитах — NEW тільки для нових (ще не показаних)
- Пам'ять переглянутих прив'язана до кожного користувача окремо

### Очистити листування

- Видаляє всі повідомлення (крім `/start`, Telegram дозволяє до 48 годин)
- Скидає список обраних категорій
- Автоматично повертає до першого екрану вибору категорій

## Технічна реалізація

### Структура проєкту

```
deftech-jobs-bot/
├── bot.py          — Telegram-бот: меню, обробники, бізнес-логіка
├── feeds.py        — RSS-завантаження, парсинг, злиття, фільтрація
├── image_gen.py    — Генерація Minecraft-картинок (Pillow)
├── requirements.txt
├── .env            — BOT_TOKEN (не комітити)
├── .env.example
└── README.md
```

### Джерела даних (RSS)

Для кожної обраної категорії — 4 RSS-ендпоінти:

```
Deftech DOU {кат}    → jobs.dou.ua/vacancies/feeds/?category={кат}&search=miltech
DOU {кат}            → jobs.dou.ua/vacancies/feeds/?category={кат}&search=бронювання
Deftech Djinni {кат} → djinni.co/jobs/rss/?all_keywords={кат}&editorial=miltech
Djinni {кат}         → djinni.co/jobs/rss/?all_keywords={кат}&editorial=reservation
```

Приклад: 2 категорії → 8 запитів → 2 фінальних списки.
Приклад: 4 категорії → 16 запитів → 4 фінальних списки.

### Алгоритм злиття (двоетапний, для кожної категорії)

**Етап 1:**
```
Deftech Djinni {кат} + Djinni {кат}  →  Temp Djinni {кат}
Deftech DOU {кат}    + DOU {кат}     →  Temp DOU {кат}
```

**Етап 2** (пріоритет Djinni — при збігу видаляється з DOU):
```
Temp Djinni {кат} + Temp DOU {кат}  →  Final {кат} (MergedSource)
```

### Дедуплікація

- Ключ порівняння: `(title.strip().lower(), company.strip().lower())`
- Вакансії з порожнім `title` або `company` — **не дедуплікуються** (завжди залишаються)
- При збігу — видаляється з **secondary** (правого) списку, залишається з primary

### Фільтрація по даті

Виконується при завантаженні в `_fetch_raw()` до злиття:
- "За 1 день" → `cutoff = today - 1` (сьогодні + вчора)
- "За 7 днів" → `cutoff = today - 7`
- "Всі вакансії" → без фільтру (`days=None`)

Порівняння: спочатку `pub_dt` (datetime з RSS), fallback — парсинг `published` рядка у форматах `dd.mm.yyyy` та RFC 2822.

### Парсинг DOU title

DOU кодує всі дані в `<title>`:
```
"Посада в/на/у Компанія, [Зарплата,] Місто"
```

Парсер `_parse_dou_title`:
1. Шукає роздільники ` в `, ` на `, ` у `
2. Якщо залишок містить маркери опису ("цінності:", "шукаємо", "обов'язки") → шукає наступний роздільник
3. Витягує `salary` при наявності `$`, `€`, `грн`
4. Витягує міста через `_split_company_and_cities`
5. Валідація `company` через `_is_invalid_company` — відкидає заголовки описів (закінчується на `:`, довше 60 символів, дублює title тощо)

### Парсинг Djinni (компанія)

Джерела в пріоритеті:
1. RSS-поля `author`, `dc_creator`, `itunes_author`
2. Перший `<strong>` тег в `<description>` (якщо містить латиницю)
3. Текст після `<p>` до ` —` (якщо містить латиницю, довжина < 60)

### Визначення міста

Словник форм `_CITY_FORMS` — пошук у `title + description`:
```python
"києві"/"київ" → "Київ"
"харкові"/"харків" → "Харків"
"івано-франківську"/"івано-франківськ" → "Івано-Франківськ"
"кривому розі"/"кривий ріг" → "Кривий Ріг"
# ... та інші
```
Якщо місто не знайдено → `"не знайдено"`.

### Хешування вакансій (мітка NEW)

```python
SHA-256(f"{title.lower()}|{company.lower()}")[:16]
```

Зберігається в `bot_data["seen_{user_id}"]` як `set[str]`.
При кожному показі — нові хеші додаються до сету.

### Структура сховища даних

| Ключ | Тип | Зміст |
|------|-----|-------|
| `bot_data["hidden_{user_id}"]` | `dict[str, str]` | `{short_link: title}` — вилучені вакансії |
| `bot_data["favorites_{user_id}"]` | `dict[str, dict]` | `{short_link: {title, ...}}` — обрані |
| `bot_data["seen_{user_id}"]` | `set[str]` | Хеші переглянутих вакансій |
| `bot_data["categories_{user_id}"]` | `list[str]` | Обрані категорії пошуку |
| `chat_data["message_ids"]` | `list[int]` | ID повідомлень для очищення |
| `chat_data["start_message_id"]` | `int` | ID повідомлення `/start` |

> ⚠️ Всі дані зберігаються **в пам'яті процесу**. При перезапуску бота — скидаються.

### Флоу підтвердження показу вакансій

```
Кнопка меню
    ↓
_request_vacancies()  ← тільки зведення, без завантаження картинок
    ↓
Показує summary + кнопки [Переобрати | Ні | Так]
    ↓ Так
confirm_show()  ← тут завантажуються вакансії + генеруються картинки
    ↓
_send_vacancies()  ← відправляє з міткою NEW / Обране
```

## Встановлення та запуск

```bash
# 1. Встанови залежності
pip install -r requirements.txt

# 2. Отримай токен: @BotFather → /newbot
# 3. Створи .env
cp .env.example .env
# Встав: BOT_TOKEN=123456:ABC...

# 4. Запусти
python bot.py
```
